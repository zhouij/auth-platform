# Auth Gateway System Implementation Plan (v3)

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Build a Kotlin Spring Boot monorepo with four modules: an IAM server (user lifecycle), an OAuth2 Authorization Server (token issuance), an API Gateway (JWT validation + reverse proxy), and a sample Resource Server (RBAC reference). All database-backed services use PostgreSQL with Flyway migrations. Deployable via Docker Compose.

**Architecture:** Four independently running Spring Boot services in a single Gradle multi-project repo. A shared PostgreSQL instance holds one schema per service. docker-compose orchestrates everything.

**Tech Stack:**
- Kotlin 1.9+ / Spring Boot 3.2+
- Auth Server: Spring MVC + Spring Security OAuth2 Authorization Server 1.x + Flyway
- IAM Server: Spring MVC + Spring Security + Spring Data JPA + Flyway
- Gateway: Spring Cloud Gateway + WebFlux (stateless, no DB)
- Resource Server: Spring MVC + Spring Security Resource Server + Spring Data JPA + Flyway
- PostgreSQL 16
- Gradle multi-project build
- Docker Compose

```sql
-- V1__init_iam_schema.sql
-- IAM server base tables

CREATE TABLE roles (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE,
    description VARCHAR(200)
);

CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(100) NOT NULL UNIQUE,
    email VARCHAR(200) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    first_name VARCHAR(100),
    last_name VARCHAR(100),
    enabled BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    last_login_at TIMESTAMP
);

CREATE TABLE user_roles (
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role_id INTEGER NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
    PRIMARY KEY (user_id, role_id)
);

-- Seed default roles
```

```kotlin
package com.authserver.auth

import org.springframework.beans.factory.annotation.Value
import org.springframework.security.core.authority.SimpleGrantedAuthority
import org.springframework.security.core.userdetails.User
import org.springframework.security.core.userdetails.UserDetails
import org.springframework.security.core.userdetails.UserDetailsService
import org.springframework.security.core.userdetails.UsernameNotFoundException
import org.springframework.stereotype.Service
import org.springframework.web.reactive.function.client.WebClient
import org.springframework.web.reactive.function.client.WebClient.RequestHeadersSpec

@Service
class IamUserDetailsService(
    @Value("\${iam.server-url}")
    private val iamServerUrl: String
) : UserDetailsService {

    private val webClient = WebClient.builder()
        .baseUrl(iamServerUrl)
        .build()

    override fun loadUserByUsername(username: String): UserDetails? {
        // The authorization server calls IAM to validate credentials during
        // authorization_code flow login. However, UserDetailsService only
        // loads the user — password validation is handled by Spring Security
        // separately. We fetch user info and roles from IAM.

        val response = webClient.get()
            .uri("/api/admin/users/$username")
            .retrieve()
            .onStatus({ it.is4xxClientError }) {
                if (it.value() == 404) throw UsernameNotFoundException("User not found: $username")
                throw RuntimeException("IAM server error: ${it.value()}")
            }
            .bodyToMono(UserResponse::class.java)
            .block()

        if (response == null) {
            throw UsernameNotFoundException("User not found: $username")
        }

        val authorities = response.roles.map { SimpleGrantedAuthority("ROLE_$it") }

        return User.builder()
            .username(response.username)
            .password("{noop}") // Password validation handled by IAM
            .authorities(authorities)
            .disabled(!response.enabled)
            .build()
    }

    data class UserResponse(
        val username: String,
        val email: String,
        val roles: List<String>,
        val enabled: Boolean
    )
}
```

```kotlin
// gateway/src/main/kotlin/com/authgateway/filter/GlobalAuthFilter.kt
package com.authgateway.filter

import org.springframework.cloud.gateway.filter.GatewayFilterChain
import org.springframework.cloud.gateway.filter.GlobalFilter
import org.springframework.core.Ordered
import org.springframework.http.HttpHeaders
import org.springframework.http.HttpStatus
import org.springframework.security.oauth2.server.resource.authentication.BearerTokenAuthentication
import org.springframework.stereotype.Component
import org.springframework.web.server.ServerWebExchange
import reactor.core.publisher.Mono

@Component
class GlobalAuthFilter : GlobalFilter, Ordered {

    override fun filter(
        exchange: ServerWebExchange,
        chain: GatewayFilterChain
    ): Mono<Void> {
        val path = exchange.request.uri.path

        // Allow actuator paths without auth
        if (path.startsWith("/actuator/")) return chain.filter(exchange)

        val auth = exchange.principal
            .as(BearerTokenAuthentication::class.java)

        return auth.switchIfEmpty(
            Mono.defer {
                exchange.response.statusCode = HttpStatus.UNAUTHORIZED
                exchange.response.setComplete()
            }
        ).flatMap { bearerAuth ->
            val jwt = bearerAuth.token

            val mutatedExchange = exchange.mutate()
                .request { req ->
                    req.header(HttpHeaders.AUTHORIZATION, "Bearer ${jwt.rawToken}")
                        .header("X-User-Id", jwt.subject)
                        .header("X-User-Scope", jwt.scopes?.joinToString(",") ?: "none")
                        .header("X-Client-Id", jwt.claims["clientId"]?.toString() ?: "unknown")
                        .header("X-User-Roles",
                            (jwt.claims["roles"] as? Array<*>)?.joinToString(",") ?: "none")
                }
                .build()

            chain.filter(mutatedExchange)
        }.onErrorResume(Exception::class.java) {
            exchange.response.statusCode = HttpStatus.UNAUTHORIZED
            exchange.response.setComplete()
        }
    }

    override fun getOrder(): Int = HIGHEST_PRECEDENCE
}
```

```kotlin
// resource-server/src/main/kotlin/com/resourceserver/config/CompositeJwtGrantedAuthoritiesConverter.kt
package com.resourceserver.config

import org.springframework.security.core.GrantedAuthority
import org.springframework.security.core.authority.SimpleGrantedAuthority
import org.springframework.security.oauth2.server.resource.authentication.JwtAuthenticationConverter
import org.springframework.security.oauth2.server.resource.authentication.JwtGrantedAuthoritiesConverter

class CompositeJwtGrantedAuthoritiesConverter : JwtGrantedAuthoritiesConverter() {

    override fun convert(jwt: org.springframework.security.oauth2.jwt.Jwt): Collection<GrantedAuthority> {
        val authorities = mutableSetOf<GrantedAuthority>()

        // OAuth2 scopes -> SCOPE_read, SCOPE_write
        jwt.scope?.mapTo(authorities) { SimpleGrantedAuthority("SCOPE_$it") }

        // Custom "roles" claim -> ROLE_ADMIN, ROLE_USER
        @Suppress("UNCHECKED_CAST")
        val roles = jwt.claims["roles"] as? Array<String>
        roles?.forEach { authorities.add(SimpleGrantedAuthority("ROLE_$it")) }

        // Standard resource server authority
        authorities.add(JwtAuthenticationConverter.DEFAULT_AUTHORITY)

        return authorities
    }
}
```

```kotlin
package com.resourceserver.service

import org.springframework.stereotype.Service

@Service
class AuthorizationChecker {
    fun canRead(requesterId: String, ownerId: String, role: String?): Boolean =
        isOwner(requesterId, ownerId) || isAdmin(role) || isUser(role)

    fun canWrite(requesterId: String, ownerId: String, role: String?): Boolean =
        isOwner(requesterId, ownerId) || isAdmin(role)

    fun canDelete(requesterId: String, ownerId: String, role: String?): Boolean =
        isOwner(requesterId, ownerId) || isAdmin(role)

    private fun isOwner(requesterId: String, ownerId: String) = requesterId == ownerId
    private fun isAdmin(role: String?) = role?.uppercase() == "ADMIN"
    private fun isUser(role: String?) = role?.uppercase() in setOf("USER", "ADMIN")
}
```

## Authorization Patterns in Resource Server

The resource-server demonstrates these patterns:

1. **`@PreAuthorize` scope check:** `@PreAuthorize("#oauth2.hasScope('write')")`
2. **`@PreAuthorize` role check:** `@PreAuthorize("hasRole('ADMIN')")`
3. **Owner-based resource access:** `AuthorizationChecker.canRead(requesterId, ownerId, role)`
4. **URL-level security:** `permitAll()` for public paths
5. **Composite JWT authorities:** Both `SCOPE_` and `ROLE_` from JWT claims

## Registered OAuth2 Clients

Clients are stored in PostgreSQL (seeded by Flyway V1 migration):

| Client ID | Grant Types | Scopes | Secret |
|---|---|---|---|
| `web-client` | authorization_code, refresh_token | openid, read, write | `secret` |
| `service-client` | client_credentials | read, write | `service-secret` |
| `gateway-client` | client_credentials | read | `gateway-secret` |

## Flyway Migrations

Each service manages its own schema via Flyway. Migrations live in `src/main/resources/db/migration/`.

To add a new migration: create `V2__add_something.sql` in the appropriate module's migration directory.

```bash
ACCESS=$(echo "$TOKEN" | grep -o '"access_token":"[^"]*"' | cut -d'"' -f4)

curl -s -H "Authorization: Bearer $ACCESS" http://localhost:8080/api/whoami
echo

curl -s http://localhost:8080/api/public/status
```

## Design Decisions

1. **Separate IAM + Auth Server**: Keeps OAuth2 token issuance focused on protocol compliance while IAM handles user lifecycle business logic independently.

2. **PostgreSQL for all services**: Each service has its own database (`authdb`, `iamdb`, `resourcedb`) with its own Flyway-managed schema. Proper database isolation per service.

3. **Flyway per module**: Each module owns its migrations separately. No shared migration scripts. Schema changes are atomic per service.

4. **HTTP delegation**: Auth server validates credentials via REST call to IAM server. No shared database coupling between auth and IAM.

5. **Gateway stateless**: No database for the gateway — it's pure routing with JWT validation against the auth server's JWKS endpoint.

6. **Resource patterns in resource-server**: Demonstrates `@PreAuthorize` (scope + role), owner-based access, and composite JWT authorities. Ready to be used as a template for new domain services.
